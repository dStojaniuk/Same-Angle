# Architecture

Bun installs the frontend dependencies and Turborepo runs workspace tasks. Each workspace owns its commands. The backend uses uv to manage Python independently.

- `backend/src/same_angle/imaging.py` operates on images in memory. The example handles files and produces the teaching images.
- `frontend/` runs the editor with React and Vite. It draws the outline and perspective grid in oriented image coordinates, then sends one render request after approval.
- `evals/` describes how to assess visual quality once the editor produces room renders.

Vite proxies `POST /api/floor-render` to FastAPI on loopback. The browser decodes an uploaded photo into an oriented, static 8-bit sRGB PNG and shares that raster between the editor and renderer. The multipart request contains the working image and a JSON `plan` with its dimensions, outline vertices, and four grid corners. The bundled sample uses a static WebP. Corner order is top left, top right, bottom right, bottom left. All points use pixel coordinates in the oriented image. The grid previews six board widths along the far edge and four depth intervals.

The renderer accepts working PNGs up to 100 MiB so lossless encoding can cover the 24 MP import limit. The limit for JPEG and WebP requests is 25 MiB. Direct requests with APNG, 16-bit PNG, or PNG color metadata that cannot be preserved get a 422 response asking the caller to prepare the photo in the editor. Python verifies the dimensions, projects a repeating oak texture from the same corners, and composites it only inside the outline. The endpoint returns a PNG with the original framing and dimensions. `backend/src/same_angle/floor.py` owns the projection and compositing. `apply_mask` in the imaging module remains the introductory recoloring exercise.

The editor keeps one undo and redo history for the floor outline and grid. IndexedDB stores the current draft and the source file in separate stores in the browser. Draft writes leave the original file in place and verify the saved revision before replacing coordinates. Opening the saved projects list refreshes it from IndexedDB and keeps drafts pending in the active tab. Reopening a project restores its pending edits when present. After a conflict, the editor can save those edits as a separate project and open the saved version for continued work. The editor checks the render's PNG signature and chunk boundaries, decodes it, and checks its dimensions before enabling comparison and download.

**Edge-based calibration.** Fit marks associate two oriented image pixels with an architectural edge of a rectangular room. The user supplies approximate dimensions. The fit minimizes the perpendicular pixel distances to the projected edges using a pinhole camera. It estimates the pose and horizontal field of view, and rejects underdetermined input. Check-only marks report RMS and maximum deviation without entering the fit. Segments that overlap a fitted span cannot serve as checks. The camera projects the bed and maps image pixels on the floor to texture tiles in room coordinates. The calibrated floor request supplies this mapping as a row-major 3 × 3 inverse homography in place of the four grid corners. The backend applies it within the outline and rejects a mask that reaches the camera horizon. The editor composites the projected bed onto that floor PNG for comparison and export.

**Style editing.** `POST /api/style-render` receives the prepared photo, prompt, editable polygons and protected polygons. It can also receive a static edited image. Without that image, the configured backend sends the prompt and a translucent overlay marking the editable areas to the Images API. The provider adapter pads to a supported frame and crops back to the original bounds. Both paths use the same local compositor. The editable pixel mask is the union of edit polygons minus the union of protected polygons. A same-aspect-ratio candidate can be scaled to the original dimensions. The blend tapers inward by default. Turning off feathering applies the edit up to the mask boundary. Both modes copy the original pixels everywhere outside the effective mask. The style status endpoint reports whether the backend has a key configured. Provider connectivity is checked by the actual generation request. This preserves annotated landmarks. Areas hidden by removed objects are inferred by the image model.

**Local Codex provider.** With `ENABLE_CODEX_IMAGEGEN=1`, the status endpoint also reports whether the CLI is installed and signed in with ChatGPT. The render endpoint accepts a multipart `provider=codex` field from the same loopback origin. The adapter runs a read-only `codex exec` session, with shell and agent delegation tools disabled, and attaches a square padded version of the photo and its guide. On CLI 0.171.0, the JSONL stream identifies the run and its completed turn. The native PNG is read from the matching directory under Codex's generated images. The adapter verifies the returned canvas, has a 180-second generation deadline and releases its local slot on failure. The known source padding is removed and the candidate goes through the shared compositor.

**Quick floor and edge review.** `POST /api/floor-suggestion` accepts the prepared image and a light-oak prompt. A bounded local color analysis finds a floor region connected to the bottom of the photo. The default grid requires two converging side edges and an uninterrupted region. With a configured Fast-SCNN checkpoint, the optional CPU path checks straight edges against the photo and verifies that the simplified outline fits inside the predicted mask. The editor uses a valid suggestion with `/api/floor-render` or opens the existing outline or grid editor for correction. The perspective review measures pairs of endpoints and a checkpoint in the same oriented coordinates. It reports the largest point displacement and angle change on either side of the checkpoint. The trial limits are 2 pixels at fit-to-window scale or 2 degrees. The review describes the marked edges and requires two directions before reporting a match.
